# Gateway: запуск и проверки

Реализованы семь публичных операций Hotels Booking System и
`GET /manage/health` на порту 8080. Публичные ответы соответствуют OpenAPI
и Postman варианта 2. Внутренние контракты трех зависимых сервисов описаны
в [gateway-internal-api.md](gateway-internal-api.md), архитектура —
в [gateway-design.md](gateway-design.md).

Прикладной слой содержит один `application.Service` с семью именованными
методами. Четыре контроллера получают его через небольшие потребительские
интерфейсы; сам сервис получает три внешних порта, генератор UUID и таймаут
компенсаций через конструктор. Методы распределены по файлам по назначению.

## Локальный запуск

Требуются Go 1.27 и RabbitMQ (`docker compose up -d --wait rabbitmq`). Версии Go-модуля и Docker builder закреплены в проекте.

```sh
go run ./cmd/gateway
```

```sh
curl http://localhost:8080/manage/health
```

Gateway подключается к RabbitMQ и объявляет очереди до запуска HTTP-сервера. Health возвращает `200` и
`{"status":"UP"}` при открытом соединении с RabbitMQ; после обнаружения потери связи клиентом — `503`.
Для выполнения бизнес-запросов нужны реализованные Reservation, Payment и Loyalty.
Полный запуск описан в [services.md](services.md). Недоступность зависимости
обрабатывается по правилам деградации: критичный Reservation/Payment дает `500`,
Loyalty — `503`; некритичные части ответа заменяются `{}`. Превышение общего
срока сценария без ошибки зависимости дает `504`. Gateway не обращается к PostgreSQL напрямую.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `RABBITMQ_URL` | `amqp://booking:booking@localhost:5672/` | Подключение к RabbitMQ, учетные данные и virtual host; поддерживается amqps |
| `BROKER_TIMEOUT` | `2s` | Таймаут подключения и ожидания подтверждения публикации |
| `GATEWAY_ADDR` | `:8080` | Адрес HTTP-сервера |
| `RESERVATION_URL` | `http://localhost:8070` | Базовый URL Reservation |
| `PAYMENT_URL` | `http://localhost:8060` | Базовый URL Payment |
| `LOYALTY_URL` | `http://localhost:8050` | Базовый URL Loyalty |
| `REQUEST_TIMEOUT` | `5s` | Общий срок выполнения сценария |
| `CLIENT_TIMEOUT` | `2s` | Срок отдельного исходящего HTTP-запроса |
| `CLEANUP_TIMEOUT` | `2s` | Общий дополнительный срок компенсаций |
| `SHUTDOWN_TIMEOUT` | `10s` | Ожидание завершения запросов при SIGINT/SIGTERM |
| `CIRCUIT_THRESHOLD` | `3` | Число последних сбоев, времена которых хранятся для проверки открытия цепи |
| `CIRCUIT_WINDOW` | `10s` | Максимальная разница времени между самым старым и новым из последних CIRCUIT_THRESHOLD сбоев |
| `CIRCUIT_TIMEOUT` | `10s` | Пауза перед одним пробным запросом |
| `RETRY_INTERVAL` | `10s` | Пауза перед первой и следующей попыткой фоновой компенсации |
| `RETRY_CAPACITY` | `1024` | Лимит готовых сообщений в каждой из двух очередей; переполнение отклоняет публикацию |

Пустое значение использует default. Невалидные адреса, URL и неположительные
таймауты отклоняются при запуске. `SHUTDOWN_TIMEOUT` должен быть не меньше
`CLEANUP_TIMEOUT`. Исходящие запросы не следуют перенаправлениям.

## Docker

```sh
docker compose up -d --build --wait --wait-timeout 120
docker compose logs gateway
docker compose down
```

Образ запускается непривилегированным пользователем и содержит статический
бинарный файл. Healthcheck выполняет `/gateway -healthcheck`.
Compose поднимает PostgreSQL, применяет миграции основных сервисов и ожидает
готовности RabbitMQ, Reservation, Payment и Loyalty перед стартом Gateway.
RabbitMQ хранит данные в volume `rabbitmq-data`. Очереди durable/quorum, сообщения
persistent. Management UI доступен на http://localhost:15672 (booking/booking в локальном Compose).

## Проверки

```sh
go vet ./...
RABBITMQ_TEST_URL=amqp://booking:booking@localhost:5672/ go test -race ./...
go build ./cmd/gateway
```

- Unit-тесты сценариев используют тестовые реализации портов и проверяют
  агрегацию, владельца, скидку до изменения лояльности, частичные записи
  с потерянными ответами, компенсации и повтор отмены.
- Тесты контроллеров используют `httptest.ResponseRecorder` и сравнивают
  публичный JSON, валидацию, статусы, пустые массивы и общий deadline.
- Тесты HTTP-клиентов используют локальные `httptest.Server`, проверяют
  внутренние URL/методы/тела, ошибки и отмену запросов.
- Компонентный тест в `cmd/gateway/main_test.go` проверяет реальную сборку
  Gateway и полный цикл бронирования через HTTP-имитации трех зависимостей.
  Эти имитации не заменяют приемку с настоящими сервисами и PostgreSQL.

Тесты были написаны до реализации и прошли отдельное агентское ревью.
Реализация прошла независимое ревью другим агентом; замечания по кодированию
dot-сегментов имен пользователей исправлены и защищены регрессионным тестом.

Workflow `.github/workflows/classroom.yml` проверяет форматирование, vet,
race-тесты, сборку Go и Docker, success/failover Postman, PostgreSQL-репозитории
на отдельных базах и системные сценарии после запуска Compose.
Коллекция Postman указана как `v2/` и не изменялась ради тестов.

## Пределы восстановления

Компенсации создания сначала выполняются синхронно с отдельным таймаутом.
Неудавшиеся команды передаются фоновой очереди. При отмене бронирования отказ
Loyalty также передает снятие учета в очередь: клиент получает `204`, оплата
и бронь отменены, счетчик лояльности исправляется после восстановления сервиса.

Очередь реализована стандартными механизмами RabbitMQ, через официальный клиент
`github.com/rabbitmq/amqp091-go`. В Gateway остается код публикации и обработчик
команд; хранения сообщений, таймеров, захватов задач и циклов опроса в нем нет.

- `gateway.cleanup.delay`: durable quorum queue с TTL `RETRY_INTERVAL` и dead-letter
  routing в `gateway.cleanup`. В нее публикуются новые команды компенсации.
- `gateway.cleanup`: durable quorum queue, которую слушает consumer Gateway с
  `prefetch=1` и ручными подтверждениями. Ошибка обработки вызывает Nack без requeue:
  dead-letter routing направляет сообщение обратно в delay-очередь.

Первая и последующие попытки происходят не раньше `RETRY_INTERVAL` (по умолчанию
10 секунд). TTL и лимит объявляются как аргументы durable-очередей; их изменение
для уже существующих очередей требует согласованного обновления конфигурации брокера
или пересоздания после обработки накопленных сообщений. Приложение не удаляет
очереди автоматически при несовпадении аргументов. Используется встроенное at-least-once dead-lettering quorum queues и
`reject-publish` при переполнении. Публикация persistent-сообщения считается успешной
только после publisher confirm; `mandatory` не позволяет принять потерю маршрута.
При ошибке брокера или отрицательном подтверждении Gateway возвращает ошибку.

Успех компенсации подтверждается Ack. При разрыве соединения неподтвержденные
сообщения возвращает брокер. Восстановление соединений, каналов, объявленных очередей
и consumer выполняет библиотека AMQP (Recovery). RabbitMQ и Gateway также имеют
restart policy в Compose. Heartbeat обнаруживает разрыв соединения, health отражает
состояние подключения. До обнаружения разрыва health может временно оставаться 200.

Собственной дедупликации больше нет: повторные сообщения разрешены, а бизнес-команды
идемпотентны по исходному UUID. Доставка как минимум однократная; exactly-once и общая
ACID-транзакция между сервисами не обещаются. Схема отката — оркестрация Saga в Gateway:
прямые шаги выполняются через HTTP, обратные команды при необходимости уходят в брокер.
Само задание требует откат/повтор, но не требует конкретного фреймворка Saga.

Очереди переживают перезапуск Gateway и брокера при сохраненном volume.
`docker compose down -v` удаляет volumes PostgreSQL и RabbitMQ. В Compose один узел
брокера: дисковая сохранность есть, отказоустойчивость к потере узла не обеспечивается.
Circuit Breaker остается в памяти. Полного сохраняемого журнала Saga/outbox нет:
падение между HTTP-записью и публикацией компенсации все еще может оставить частичные изменения.

Для интеграционных тестов задайте `RABBITMQ_TEST_URL` на тестовый брокер. Каждый тест
создает уникальные очереди и удаляет только их. Без переменной тесты адаптера и worker
пропускаются; CI поднимает RabbitMQ и запускает их.

`make test-broker-recovery` проверяет сохранение компенсации при перезапуске брокера
и Gateway и идемпотентное выполнение после восстановления Loyalty. Скрипт временно
останавливает эти контейнеры; запускать на тестовой системе.
